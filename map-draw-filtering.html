1Capture the stroke (pointer events)

Listen to pointerdown / pointermove / pointerup on a transparent overlay above the Leaflet map (in the CRM: map.dragging.disable() while draw-mode is on). Sample a vertex only when the pointer moved ≥ 6 px from the last one — this alone drops ~80% of raw events.

// px → geo: Leaflet gives you this for free
overlay.addEventListener("pointermove", e => {
  if (!drawing) return;
  const pt = { x: e.offsetX, y: e.offsetY };
  if (dist(pt, last) < 6) return;      // distance throttle
  const ll = map.containerPointToLatLng([pt.x, pt.y]);
  ring.push([ll.lng, ll.lat]);              // GeoJSON order: [lng, lat]!
  last = pt; redrawPreview(ring);
});

2Simplify (Ramer–Douglas–Peucker)

A 4-second stroke still yields 200–400 vertices. RDP with a tolerance of ~8–15 meters cuts it to 20–40 without visible change. Fewer vertices = cheaper point-in-polygon on every listing and a smaller payload to the server.

function rdp(points, eps) {
  if (points.length < 3) return points;
  let maxD = 0, idx = 0;
  const [a, b] = [points[0], points[points.length - 1]];
  for (let i = 1; i < points.length - 1; i++) {
    const d = perpendicularDist(points[i], a, b);
    if (d > maxD) { maxD = d; idx = i; }
  }
  return maxD > eps
    ? [...rdp(points.slice(0, idx + 1), eps).slice(0, -1), ...rdp(points.slice(idx), eps)]
    : [a, b];
}

3Close the ring → GeoJSON polygon

Append the first vertex to the end (GeoJSON rings must be closed), wrap as a Polygon. Reject degenerate shapes client-side: fewer than 4 vertices or area under ~0.5 ha.

ring.push(ring[0]);
const zone = { type: "Polygon", coordinates: [ring] };

4Instant client preview — bbox + ray casting

For the listings already loaded on screen (a few hundred), filter locally so the rieltor sees the result the same frame. Two stages: a cheap bounding-box test throws away most points, then ray casting decides the rest. This exact function powers the demo above.

function inPolygon(p, ring) {          // ray casting, O(vertices)
  let inside = false;
  for (let i = 0, j = ring.length - 1; i < ring.length; j = i++) {
    const [xi, yi] = ring[i], [xj, yj] = ring[j];
    if (((yi > p[1]) !== (yj > p[1])) &&
        (p[0] < (xj - xi) * (p[1] - yi) / (yj - yi) + xi))
      inside = !inside;                   // odd crossings = inside
  }
  return inside;
}
// bbox prefilter first:
const bb = bboxOf(ring);
const preview = listings.filter(l =>
  l.lng >= bb.minX && l.lng <= bb.maxX &&
  l.lat >= bb.minY && l.lat <= bb.maxY &&
  inPolygon([l.lng, l.lat], ring));

5Authoritative server query

The client preview is cosmetic; the server answers with the real set (all listings, not just loaded ones). With PostGIS the polygon goes in as GeoJSON and the GiST index does the bbox stage for you (ST_Contains internally uses the && index operator first).

-- one-time schema
ALTER TABLE listings ADD COLUMN geom geometry(Point, 4326);
UPDATE listings SET geom = ST_SetSRID(ST_MakePoint(lng, lat), 4326);
CREATE INDEX listings_geom_gix ON listings USING GIST (geom);

-- per draw (polygon arrives as GeoJSON string :zone)
SELECT id, price, area_m2, ptype
FROM listings
WHERE status = 'active'
  AND ST_Contains(
        ST_SetSRID(ST_GeomFromGeoJSON(:zone), 4326),
        geom);
# Django (GeoDjango) equivalent — the CRM backend is Django
from django.contrib.gis.geos import GEOSGeometry
zone = GEOSGeometry(request.body["zone"])      # GeoJSON in
if zone.num_coords > 200 or not zone.valid:   # server-side guards
    zone = zone.buffer(0)                       # fix self-intersections
qs = Listing.objects.filter(status="active", geom__within=zone)
No PostGIS (DynamoDB path)? Cover the polygon's bbox with geohash cells (precision 6–7), query the geohash GSI for candidates, then run the same ray-casting check in the Lambda. Same three stages — cheap cover, index fetch, exact test.

6Zone statistics (the "Zona statistikası" card)

One aggregate query on the same filtered set — median via percentile_cont, and the Əlimyandı count reuses the zone median with the threshold θ (e.g. 15%).

SELECT
  count(*)                                            AS total,
  percentile_cont(0.5) WITHIN GROUP (ORDER BY price/area_m2) AS median_m2,
  count(*) FILTER (WHERE price/area_m2 <
        (SELECT percentile_cont(0.5) WITHIN GROUP (ORDER BY price/area_m2)
         FROM zone_set) * 0.85)                     AS alimyandi
FROM zone_set;   -- zone_set = CTE with the ST_Contains filter from step 5
